# prismatix — a local, privacy-first developer & business copilot

An OpenCode-style terminal copilot built on a **small open-weight model running
fully on your own laptop**. No cloud, no API keys, no data leaves the machine. 

**What it does**
- `/code` — writes Python (plan → runnable code block → edge-case note)
- `/sql` — turns business questions into SQL for the Northwind schema
- `/brief` — 3-sentence manager brief from raw notes (numbers first)
- `/email` — short customer/team emails in the house voice
- `/rag` — answers from *your* local knowledge base, with citations
- `/index`, `/stats`, `/reset`, `/quit`

**How it was modified** (the portfolio part)
1. **Base model**: `Qwen/Qwen3.5-4B` (Apache-2.0), run in 4-bit via Apple **MLX**
   (`mlx-community/Qwen3.5-4B-4bit`). Accurate description: *we ran a
   quantized, open-weight 4B model locally and changed its behaviour with two
   techniques — retrieval and a LoRA adapter — we did not pre-train anything.*
2. **RAG**: chunks of local markdown docs embedded with `bge-small-en-v1.5`
   (MIT, ONNX Runtime — no PyTorch), exact cosine search in SQLite.
3. **LoRA** (rank 16, ~300 steps on the 16 GB MacBook, `mlx_lm.lora`,
   `--mask-prompt`) on a **self-authored** synthetic dataset that teaches the
   house answer format — *style transfer, not knowledge injection*.
4. **Evaluation**: 16 checkable tasks (Python graded by hidden unit tests,
   SQL executed against a seeded SQLite DB, business text scored by
   deterministic rubrics). Base vs LoRA numbers in [Results](#results).

## Run it

```bash
uv venv --python 3.12 && source .venv/bin/activate
uv pip install -e '.[dev]'

python scripts/smoke_test.py          # Milestone 1: does inference work?
python -m eval.run_eval --out artifacts/eval_runs/base.jsonl   # Milestone 2
python -m prismatix --headless '/sql revenue by region'        # Milestone 3
python -m prismatix                   # the TUI
```

RAG (first run downloads a 110 MB embedding model to `~/.cache/fastembed`):

```bash
python -m prismatix --headless '/rag what is the refund window?'
```

Fine-tune (needs ~20 min and ~10 GB free unified memory; do it with the
browser/IDE closed on a 16 GB machine):

```bash
python -m training.build_dataset      # regenerates the synthetic data (fixed seed)
python -m training.split              # 360 train / 40 valid
bash training/train.sh                # writes adapters/prismatix-style
python -m eval.run_eval --adapter adapters/prismatix-style \
    --out artifacts/eval_runs/lora.jsonl
```

## Honest scope statement (for the university write-up)
- We did **not** train a model from scratch; we fine-tuned ~16M of 4.2B
  parameters (0.386%) as a LoRA rank-16 adapter (~62 MB) for a few hundred
  steps on Apple Silicon.
- **One full LoRA run failed loudly** (see LOG.md #14-15): an over-aggressive
  recipe (lr 1e-4 x scale 20) drove train loss to 0.09 but made every
  generation degenerate -> benchmark 0/16. We retrained with lr 1e-5.
  Lesson recorded: *val loss alone does not imply usable output — score
  generations.*
- The training data is **synthetic and self-authored**: it teaches a format,
  and the evaluation measures format generalization plus task correctness —
  the same 16-instance benchmark scored with deterministic checks.
- The SQL portion of the benchmark harness itself was debugged mid-project
  (grader fixes changed a first logged score of 10/16 to a corrected 13/16
  with *no model change*); both numbers are kept in LOG.md.
